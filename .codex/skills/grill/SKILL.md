# 설계 그릴

기계적인 DoD가 답할 수 없는 결정 질문만 한다. 점수화·자동 수정은 하지 않는다.

## 범위

`AGENTS.md`, `.codex/harness-context.md`, `.codex/ssot-index.md`를 읽는다. 기준선 diff, `git diff HEAD`, untracked 파일의 합집합을 대상으로 하며, 영향 도메인의 권위 문서만 읽는다.

## 질문 축

적용되는 축마다 파일:줄 또는 문서 절과 이유를 인용해 1~3개 질문을 한다.

1. Source·권한·공개 시각은 증거가 있는가?
2. 데이터 계보, 정정, 원본 보존, 접근 경계는 명확한가?
3. 변경이 정본·계약·호환성·마이그레이션을 바꾸는가?
4. 표본·누수·권한·실행·오류 영향이 명시됐는가?
5. 재현 입력, 설정, 코드 버전, 환경, 보고 계보를 식별할 수 있는가?
6. 작업목록·진행기록·ADR·용어 갱신이 필요한가?

빈 절, 일반론, `PASS`/`FAIL`, 자동 ADR 편집을 출력하지 않는다.
