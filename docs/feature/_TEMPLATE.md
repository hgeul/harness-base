# [기능명] 기능정의서

> **What.** 결정사항 + 결정이유 + 단계 의존성.
> 스펙(How)·구현은 `docs/spec/` 에 따로.

## 1. 개요

- 기능 한 줄: 무엇을 누구에게 왜 제공하는가
- 트리거 사건: 왜 이 기능을 지금 하나
- 관련 도메인: 코드 위치

## 2. 결정사항과 결정이유

모든 결정은 **결정안 + 결정이유** 한 쌍으로 적는다. "이렇게 한다"만 적으면 6개월 뒤 왜 그랬는지 사라진다.

| 결정 항목 | 결정안 | 결정이유 |
|---|---|---|
| (예) 외부 호출 timeout | 5초 | 외부 hang 시 사용자 대기 한계 |
|  |  |  |

## 3. 단계 의존성

다음 단계에 영향 주는 결정은 이번 단계에서 "선행 설계"로 먼저 박는다.

| 단계 | 작업 내용 |
|---|---|
| 선행 설계 | (예) 스키마에 컬럼만 추가 (기본값) |
| 정식 도입 | (예) 실제 로직 활성화 |

## 4. 비기능 요구

- 성능·동시성 / 보안·권한 / 호환성(break change 여부)
