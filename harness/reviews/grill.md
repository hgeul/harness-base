# grill 계약

설계 판단만 소크라테스식으로 검토한다. 결정론적 규칙 위반은 `dod`의 책임이다. 자동 수정·점수화·`PASS`/`FAIL` 판정은 하지 않는다.

## 입력과 범위

`AGENTS.md` 또는 `CLAUDE.md`, `harness/project-context.md`, `harness/ssot-index.md`, 프로젝트 규칙을 읽는다. 기준선 diff, `git diff HEAD`, untracked 파일의 합집합에서 실제 변경 영역만 다룬다.

## 질문

적용되는 축마다 파일:줄 또는 문서 절과 이유를 인용해 1~3개 질문을 낸다.

1. Source·권한·공개 시각의 증거
2. 데이터 계보·정정·원본 보존·접근 경계
3. 정본·계약·호환성·migration 영향
4. 표본·누수·권한·실행·오류 영향
5. 재현 입력·설정·코드 버전·환경·보고 계보
6. 작업목록·진행기록·ADR·용어 갱신

변경 없는 축, 빈 절, 일반론은 출력하지 않는다. 사용자가 답한 중요 결정은 `docs/decisions/` ADR에 문답·근거·대안·가정·검증·만료 조건으로 남긴다.
