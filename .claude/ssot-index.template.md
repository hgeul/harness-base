# SSOT 인덱스 (<PROJECT_NAME>) [PROJECT overlay]

이 프로젝트의 "진실 원천" 등록부. 흩어진 진실(코드/규칙/정책/외부계약)을 한 장에 매핑하고,
각각을 무엇으로 검증하는지 적는다. `/drift`·dod `[N]` 의 점검 대상 목록이다.

## 진실 기준 원칙

- 내부 동작의 진실 = **코드**. 문서가 코드와 어긋나면 코드가 정답, 문서를 고친다.
- 외부 계약의 진실 = **외부 스펙 문서**. 우리 코드가 따라간다.
- 스키마의 진실 = **DB / 마이그레이션**.
- marker 블록으로 외부 도구가 관리하는 영역은 그 도구가 주인. 드리프트 검사 제외(INFO).

## 등록부

| 진실 도메인 | 권위 원천(문서) | 진실 기준 | 검증 방법 |
|---|---|---|---|
| (예) 외부연동 인증·캐시 | `.claude/rules/<external>.md` | 코드 | `<Client>.ext` 와 대조 |
| (예) 외부 API 계약 | `docs/reference/<api>.md` | 외부 스펙 | 인터페이스 정의서 버전 |
| (예) 데이터 격리 | `.claude/rules/<entity>.md` | 코드 | 쿼리 격리 조건 |
| (예) 스키마 | `docs/migration/*.sql` | DB | 엔티티 ↔ SQL ↔ 실DB |
| (예) 커밋/워크플로 | `CLAUDE.md`, 훅 | 훅(실행) | 훅 정규식이 실제 게이트 |

## 문서 수명주기 지도

| 문서 종류 | 답하는 질문 | 현재 정본 여부 | drift 점검 | 완료 후 처리 |
|---|---|---|---|---|
| 프로젝트 컨텍스트·정본 | 지금 무엇이 참인가 | 예 | 대상 | 현재 기준으로 갱신 |
| `docs/backlog/` | 결정됐지만 무엇이 남았는가 | 작업 상태만 | 대상 | 완료 항목 제거 후 progress 연결 |
| `docs/progress/` | 실제로 무엇을 했는가 | 아니오, 당시 사실 | **제외** | 시간순 보존; 오류는 정정 이력 추가 |
| `docs/decisions/` | 왜 이 결정을 했는가 | 채택된 결정에 한함 | 대상 | 대체 ADR을 연결하고 상태 변경 |

progress 만 drift 점검에서 빼는 이유는 과거 사실의 앵커가 낡는 게 정상이기 때문이다.
넣으면 오탐이 쌓여 Tier1 신호가 죽는다. 근거는 `HARNESS.md` 「기록 수명주기」.

## 갱신 규칙

- 새 진실 도메인(새 외부연동, 새 정책)이 생기면 여기 한 줄 추가.
- 권위 원천 파일을 옮기거나 이름 바꾸면 여기부터 고친다.
- progress의 과거 상태를 현재 정본으로 등록하지 않는다. 반복해서 참조할 규칙은 정본이나 정책으로 승격한다.
